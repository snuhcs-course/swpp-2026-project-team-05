# FrameLESS 분석 파이프라인 구조

Iteration 2의 서버 분석 경로를 수정할 때 지켜야 할 단계·계약·실패 정책을 정리한다. 실행 진입점은 `POST /api/analyze`, 오케스트레이터는 `server/analysis/v2/pipeline.py`다.

## 데이터 흐름

```text
URL 입력 → 기사 본문 수집 → 입력 기사 사건·주장 추출
        → NAVER 검색 메타데이터 → 후보 순위
        → 후보 본문 수집·동일 사건 검증·부족분 보충
        → 화면에 표시할 기사 선택(최대 3개)
        → 기사별 I1–I5 → 주장별 A–G → Android 응답 변환
```

| 단계 | 책임 | 다음 단계에 넘기는 확인된 정보 |
| --- | --- | --- |
| 입력·수집 | URL을 검증하고 제목·본문·문장 번호를 만든다. | 입력 기사 `S0` |
| 입력 기사 분석 | 원문의 인용 구간에 연결된 사건·주장·검색어를 만든다. | 주장 ID와 원문 근거 |
| 검색·후보 선정 | NAVER에서 메타데이터를 수집하고 후보를 정렬한다. | 후보 URL과 검색 출처 |
| 본문 검증 | 본문을 읽고 같은 사건·주장 관계를 원문 근거로 확인한다. | 검증된 후보와 관계 판정 |
| 표시 범위 | 서로 다른 주장의 근거를 우선하면서 표시 기사 수를 제한한다. | Android에 표시할 기사 ID |
| 정보 루브릭 | `S0`와 관련 기사 각각에서 I1–I5 근거를 찾는다. | 기사별 정보 관찰값 |
| 표현 루브릭 | 주장별 기사 표현을 비교하고 A–G의 근거와 보류 상태를 기록한다. | 주장별 표현 관찰값 |
| 응답 변환 | 서버 내부 결과를 Android 계약으로 옮긴다. | 화면 카드와 분석 상태 |

LLM이 반환한 JSON은 로컬 스키마와 원문 인용 위치로 다시 검증한다. 모델이 제시한 구절을 기사에 없는 근거로 인정하지 않는다. 한 단계의 재시도가 끝나도 검증되지 않은 항목은 `unverified` 또는 부분 실패로 남긴다.

## 결과 상태와 오류 경계

`execution_status`는 `success`, `partial`, `failed` 중 하나다. `comparison_status`는 `available`, `no_matches`, `unavailable`, `not_requested`를 구별한다. `no_matches`는 검색과 검증이 정상 수행됐으나 대응 기사가 없을 때만 사용한다. 검색·검증 실패를 발견했을 때는 `unavailable` 또는 `partial`의 오류 기록으로 남긴다.

- 입력 기사 수집·핵심 주장 분석 실패: 뒤 단계의 근거를 만들 수 없으므로 분석 실패.
- 일부 검색어·후보 수집 실패: 확보한 검증 결과는 유지하고 부분 결과.
- 관련 기사 I1–I5 실패: 그 기사 관찰값을 보류하고 다른 기사·주장 결과는 유지.
- 입력 기사 `S0`의 I1–I5 실패: 정보 루브릭 전체를 보류하고 이미 검증된 비교는 유지.
- 주장 하나의 A–G 실패: 해당 주장의 표현 항목만 보류하고 I1–I5 및 다른 주장 결과는 유지.
- Android 변환 계약 실패: 잘못된 성공 응답을 내지 않고 고정 오류 코드로 응답.

각 오류는 단계, 고정 코드, 재시도 가능 여부를 가진다. 앱은 `partial` 상태와 `unverified`를 숨기거나 점수로 바꾸면 안 된다. FrameLESS는 기사의 진위, 정치 성향, 편향 총점을 자동 판정하지 않는다.

## 운영 경계

요청 헤더 `X-Analysis-ID`와 서버 로그의 `analysis_id`로 같은 실행을 찾는다. 운영 로그는 단계·코드·시간·호출 수 같은 메타데이터만 기록한다. 기사 본문, API 키, 프롬프트, 모델 응답, 예외 traceback은 로그에 남기지 않는다. 정확한 입력·출력 스냅샷은 명시적으로 로컬 캐시/평가를 실행할 때만 생성한다.

호출 계측에서 `attempted_calls`는 SDK 호출 시도 수, `model_calls`는 JSON 객체를 받아 완료한 호출 수다. SDK 내부 재시도 횟수는 둘 다 포함하지 않는다. 비용 추정에 성공 호출 수만 사용하면 실패 호출이 빠질 수 있다.

Vercel 함수 제한은 300초다. 분석 측 실행 제한은 그보다 짧은 소프트 마감시간이며, 이미 시작된 네트워크 호출이나 SDK 내부 재시도를 강제로 취소하지는 못한다. 실제 호출 시간과 부분 결과를 로그에서 확인해야 한다.

기사 URL은 공개 HTTP(S) 도메인으로 제한한다. DNS 해석 결과가 모두 공개 IP인지 확인하고 확인된 주소에 직접 연결한다. 사용자 입력 기사 URL에는 시스템 HTTP 프록시를 사용하지 않는다. 이 제한은 회사 컴퓨터의 프록시 설정을 바꾸지 않지만, 직접 연결이 막힌 로컬 환경에서는 기사 수집이 실패할 수 있다. NAVER 검색 인증 헤더가 리다이렉트 대상에 전달되지 않도록 검색 API 리다이렉트는 차단한다.

현재 공개 API에는 사용자 인증과 인스턴스 간 공유되는 호출량 제한이 없다. 프로세스 내부의 단일 요청 슬롯은 전체 배포의 사용량 제한이 아니므로 운영 규모가 커지면 edge 또는 공유 저장소 기반 제한이 필요하다.

## 변경 검증

합성 기사와 고정 응답으로 스키마 오류, 원문 근거 오류, 모델 장애, 관련 기사 일부 실패, 기사 없는 정상 결과, Android 계약을 검증한다. 실제 모델 응답의 **의미 정확도**와 운영 지연은 별도 사람 검토와 운영 호출로 확인해야 한다. 운영 결과가 검증되기 전에는 합성 테스트 통과를 데모 성공으로 기록하지 않는다.
